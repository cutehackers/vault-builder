프로젝트 메모리 구조

프로젝트 세션은 저장소 밖 자동 메모리에만 기록합니다. vault가 그 기록을 검증해 정리하고, 프로젝트별 요약으로 만들어 다음 세션이 시작될 때 돌려줍니다. 프로젝트 저장소의 파일은 하나도 바꾸지 않습니다.

3 계층L1 빠른 메모리 · L2 vault 장기 메모리 · L3 프로젝트 요약
1~2천 토큰세션마다 hook이 넣어 주는 요약의 크기 상한

    저장소를 수정하지 않는 방법

    대안방법판단
    대안1자동 메모리. 기록 규칙이 필요하면 ~/.claude/CLAUDE.md 한 곳에사용
    대안2~/.claude/settings.json의 SessionStart hook이 요약을 출력사용
    대안3저장소 폴더의 CLAUDE.local.md. git에는 안 올라가지만 폴더에 파일이 생김사용 안 함

    vault 저장소 안에 생기는 CLAUDE.md는 이 원칙의 대상이 아닙니다.

    메모가 가는 vault

    그 프로젝트의 결정과 이력→프로젝트 vault
    팀이 합의한 내용→팀 vault · PR로만
    다른 곳에서도 쓸 지식→개인 vault

    vault 사이의 링크는 검증에서 깨지므로, 다른 vault의 내용은 원본을 raw/에 복사해 ingest합니다. 프로젝트 세션은 연결된 vault들의 요약을 함께 받습니다.

    vault-builder 설치와 삭제

    중간에 실패하면 설치 전 상태로 돌아갑니다

    vault를 처음 만들 때는 vault-builder를 씁니다. 설치는 임시 폴더에서 조립한 뒤 한 번에 옮기고, vault 밖 변경은 마지막에 합니다.

    설치 흐름

    1사전 검사Python 3.10 이상, 경로, 기존 파일
    실패하면 대상 경로를 만들지 않음
    2임시 폴더에서 조립과 자체 검사복사, manifest 초안, 검증
    실패하면 임시 폴더만 지움. 대상 경로는 생기지 않음
    3rename 한 번으로 이동vault가 한 번에 나타남
    이 시점부터 vault 사용 가능
    4vault 밖 변경hook, 연결 설정, MCP 등록
    실패하면 vault 밖 변경과 vault까지 되돌림
    5manifest 기록vault 밖 변경까지 hash와 함께
    uninstall과 doctor가 이 기록을 씀
    설치 완료

    1~2단계는 현재 진행 중인 bake 작업의 "init Python 검사 순서" 수정과 같은 일입니다.

    uninstall이 지우는 것과 남기는 것

    hook과 연결 설정은 여러 vault가 함께 쓰므로, 마지막 vault를 지울 때만 제거합니다. 지식을 지우는 것은 별도의 명시 옵션으로만 가능합니다.

    설치·삭제 원칙

    • 원칙1원자적 설치. 위 설치 흐름. 실패하면 이전 상태로 되돌림
    • 원칙2manifest가 vault 밖 변경까지 기록. 파일과 hash를 함께
    • 원칙3vault 밖은 builder 소유 파일만. settings.json에는 항목 1개
    • 원칙4지식은 지우지 않음. raw/, wiki/, scratch/, git 이력
    • 원칙5사용자가 고친 관리 파일은 남김. 목록만 출력
    • 원칙6--dry-run으로 계획 먼저. audit/apply와 같은 방식
    • 원칙7vault별 manifest는 독립. 공유 파일은 마지막 vault 삭제 때만

    명령

    install <경로> [--name]uninstall <경로> [--dry-run]doctor <경로>audit / apply

    audit와 apply는 지금도 있습니다. install, uninstall, doctor는 새로 만듭니다.
