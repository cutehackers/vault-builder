Vault 구조 지도

vault-builder 5.1.0(contract 6) 기준의 구조입니다. 앞부분은 vault 하나의 폴더 구성입니다. 뒷부분은 여러 vault가 코드 저장소, Claude Code 설정과 어떻게 연결되는지와 자동으로 도는 흐름입니다. 2026-11-18에 코드로 확인했습니다. 명령의 자세한 동작은 docs/usage.md 16절과 17절에 있습니다.

아래에서 <설정 폴더>는 환경 변수 CLAUDE_CONFIG_DIR 값이고, 값이 없으면 $HOME/.claude입니다.

vault 하나의 안

vault는 markdown wiki를 담은 git 저장소 하나입니다. 폴더마다 누가 쓰는지 정해져 있습니다.

vault 안에는 MCP 설정 파일 .mcp.json을 만들지 않습니다. MCP 서버는 사용자 설정에 하나만 등록합니다.

지식이 쌓이는 순서

  1. 원본 추가raw/에 원본을 넣습니다.
  2. 원본 등록ingest-source가 hash를 계산해 wiki/sources/에 등록 페이지를 만듭니다. 세션 파일은 등록하지 않고 claim에서 바로 인용합니다.
  3. 초안 작성LLM이 원본을 읽고 scratch/drafts/에 초안을 씁니다.
  4. 검증과 기록publish-draft가 frontmatter, 링크, 근거를 검사하고 통과하면 wiki/에 쓰고 index.md, log.md를 갱신합니다.
  5. commitscripts/release_gate.sh가 통과하면 사람이 git에 commit합니다.
  6. 사람 판단모순이나 추론한 기억은 바로 쓰지 않고 scratch/review/에 올립니다.

vault 역할

역할은 vault-map.json의 vaults.<이름>.role 값입니다. 알려진 역할은 tools/vault_migration/roles.py의 세 개입니다. 표에 없는 역할도 받고, 그런 vault는 공유 vault로 다룹니다.

저장소 하나의 이력과 세션 원문

저장소마다 하나입니다. 이름을 줘야만 연결됩니다. 세션 원문은 이 역할의 vault에만 들어갑니다. setup의 기본 위치는 $HOME/vaults/<저장소 폴더 이름>입니다.

무엇이 vault마다 있고, 무엇이 하나인가

개수항목설명
vault마다폴더와 git 저장소, tools/wiki 사본, wiki/, raw/, manifestvault끼리 파일을 공유하지 않습니다. 각 vault는 자기 tools/wiki 버전으로 검사받습니다.
machine에 하나<설정 폴더>/vault-builder/vault-map.json연결 설정입니다. vault 목록(이름, 경로, 역할, 선택 sharable)과 저장소별 project 항목(root, remote, vaults, 선택 default_write_vault)을 적습니다. version 2입니다.
machine에 하나<설정 폴더>/vault-builder/llm_wiki_router.pyMCP 라우터입니다. 상태를 두지 않고 호출마다 연결 설정을 다시 읽어 대상 vault의 cli.py를 실행합니다.
machine에 하나$HOME/.claude.json의 mcpServers.vault-wiki라우터를 실행하는 MCP 서버 항목 하나입니다. 도구 이름은 mcp__vault-wiki__<도구>이고 도구는 24개입니다. CLAUDE_CONFIG_DIR 값이 있으면 <설정 폴더>/.claude.json입니다.
machine에 하나<설정 폴더>/vault-builder/vault_hooks.py훅 실행기입니다. <설정 폴더>/settings.json의 SessionStart, PreCompact, SessionEnd 항목이 이 파일을 실행합니다.
machine에 하나<설정 폴더>/vault-builder/vault-hooks.json훅 실행기가 부를 외부 도구의 절대 경로입니다. setup이 그런 도구를 찾았을 때만 생깁니다. 없어도 vault-builder는 동작합니다.
machine에 하나$HOME/.local/bin/vault-builder, $HOME/.local/share/vault-builder설치 명령이 만든 실행 파일과 builder checkout입니다.
저장소마다vault-map.json의 projects 항목link 명령이 만듭니다. 저장소는 root 경로, origin remote URL, 폴더 이름 순서로 찾습니다.
저장소마다L1 메모 <설정 폴더>/projects/<key>/memory/Claude Code가 씁니다. vault-builder의 memory-scan은 읽기만 합니다.
 
{
  "version": 2,
  "vaults": {
    "personal": { "path": "$HOME/vault",         "role": "personal" },
    "app":      { "path": "$HOME/vaults/my-app", "role": "project" }    ← set-role로 역할을 바꿈
  },
  "projects": {
    "my-app": {
      "root": "$HOME/workspace/my-app",
      "remote": "git@github.com:example/my-app.git",
      "vaults": ["personal", "app"],                                    ← link, unlink가 바꿈
      "default_write_vault": "app"                                      ← set-default-write가 바꿈
    }
  }
}

위는 형식 예시입니다. 실제 파일에는 절대 경로가 들어갑니다. default_write_vault와 sharable은 외부 도구가 읽는 선택 필드이고, MCP 라우터는 보지 않습니다.

자동으로 도는 흐름

setup은 훅을 항상 설치합니다. install만 쓰면 --with-hooks를 줄 때만 훅이 생깁니다.

세션 시작 (SessionStart): 연결 지점

  1. Claude Code가 vault_hooks.py session-start를 실행합니다.
    자동
  2. 외부 회상 도구가 설치되어 있으면 실행기가 그 도구에 묻습니다. vault-builder 자체에는 회상 기능이 없습니다.
  3. 그 도구가 20초 안에 성공하면 출력을 세션에 넣습니다. 도구가 없거나 실패하면 아무것도 넣지 않고 세션은 평소처럼 시작합니다.

세션 수집 (PreCompact, SessionEnd)

  1. Claude Code가 vault_hooks.py capture를 실행합니다. 제한 시간은 60초입니다.
    자동
  2. 외부 도구가 수집을 맡도록 설치되어 있으면 실행기가 먼저 그 도구를 부르고, 성공하면 여기서 끝납니다.
  3. 그런 도구가 없거나 실패하면 capture --direct로 수집합니다. 세션 폴더의 저장소에 연결된 역할 project vault가 정확히 하나일 때만 그 vault의 sessions capture를 실행합니다.
  4. 수집은 raw/sessions/<agent>/에 새 part 파일만 더합니다. commit은 하지 않습니다.

wiki 도구 호출 (MCP)

  1. Claude가 mcp__vault-wiki__wiki_search 같은 도구를 부릅니다.
  2. 라우터가 연결 설정을 다시 읽고 이 세션이 닿는 vault를 구합니다. 세션 폴더가 vault이면 그 vault 하나, 아니면 저장소에 연결된 vault 전부입니다.
  3. 읽기는 닿는 vault만 합니다. 쓰기는 vault 인자가 꼭 있어야 하고 연결 설정의 어떤 vault에도 쓸 수 있습니다.
  4. 대상 vault 폴더에서 그 vault의 tools/wiki/cli.py를 실행합니다.

기억 제안 검토 (사람)

  1. agent가 추론한 기억은 review propose --draft <draft> --summary <요약>로 올라갑니다. wiki는 바뀌지 않습니다.
    agent나 외부 도구가 실행
  2. scratch/review/에 pending 항목과 draft 사본이 생깁니다.
  3. 사람이 review list로 봅니다.
  4. 사람이 review resolve <항목> --status accepted --resolution <이유>를 실행하면 draft를 발행합니다. rejected나 resolved는 항목만 닫고 wiki/log.md에 기록합니다.
