지식이 쌓이는 순서

  1. 원본 추가raw/에 문서나 메모 사본을 넣습니다.
  2. 원본 등록ingest-source가 hash를 계산해 wiki/sources/에 등록 페이지를 만듭니다.
  3. 초안 작성LLM이 원본을 읽고 scratch/drafts/에 페이지 초안을 씁니다.
  4. 검증과 기록publish-draft가 frontmatter, 링크, 근거를 검사하고 통과하면 wiki/에 씁니다. index.md, log.md, maps/도 함께 갱신합니다.
  5. commitscripts/release_gate.sh가 통과하면 git에 commit합니다.
  6. 모순 발견기존 지식과 맞지 않으면 바로 고치지 않고 scratch/review/에 올려 사람이 판단합니다.

여러 vault를 묶는 규칙 네 가지

규칙1

vault 하나는 폴더 하나이자 git 저장소 하나입니다

각 vault는 tools/wiki 사본, wiki/, raw/를 자기 폴더에 따로 가집니다.

규칙2

MCP 서버 하나는 vault 하나만 다룹니다

서버는 자기 파일 위치에서 두 단계 위 폴더를 vault로 봅니다(mcp_server.py:11). vault가 두 개면 서버도 두 개입니다.

규칙3

vault를 묶는 파일은 vault-map.json 하나뿐입니다

어떤 vault가 있는지, 어느 저장소가 어느 vault에 연결되는지를 이 파일만 알고 있습니다.

규칙4

저장소 이름이 project id입니다

git 최상위 폴더 이름(sgp-981-app)이 project id입니다. worktree에서도 원래 저장소 이름을 씁니다.

지금 구조에서 안 되는 것

  • 한계0

    install이 MCP를 등록하는 방식에 문제가 여섯 가지 있습니다 구현으로 해결

    같은 서버를 두 곳에 등록합니다(installing.py:528, :570). doctor는 지워진 .mcp.json을 다시 만들고(uninstalling.py:642-680), user scope 항목의 interpreter는 검사하지 않습니다(uninstalling.py:591-604). interpreter 경로는 python@3.12처럼 특정 버전에 고정됩니다. 쓰기 도구가 모든 세션에 노출되고, install이 ~/.claude.json 전체를 다시 씁니다.

  • 한계1

    여러 vault를 한 번에 검색하지 못합니다 닿는 vault 검색 구현됨

    MCP 서버가 vault마다 따로 떠 있어서 결과를 합쳐 주는 곳이 없습니다. 별도 repo인 vault-graph가 이 일을 하도록 만들어지고 있지만 아직 연결되지 않았습니다.

  • 한계2

    vault 폴더 세션에서 같은 도구가 두 번 보입니다 구현으로 해결

    위 지도의 MCP 동작 4번입니다. 같은 서버를 .mcp.json과 ~/.claude.json이 각각 등록하기 때문입니다.

  • 한계3

    쓰기 도구가 모든 저장소 세션에 보입니다 의도한 동작으로 유지 (W1)

    user scope 등록은 검색 도구뿐 아니라 wiki_publish_draft 같은 쓰기 도구도 모든 세션에 보여줍니다.

  • 한계4

    요약에는 그 저장소 페이지만 나옵니다

    요약 페이지는 project 값이 그 저장소 id인 페이지만 모읍니다. 여러 저장소에 공통인 규칙은 검색으로 찾아야 합니다.

  • 한계5

    저장소를 폴더 이름만으로 찾고, 연결은 손으로 합니다 구현으로 해결

    recall.sh는 project_id = root.name으로 찾습니다. 그래서 이름이 같은 저장소의 기억이 섞이고, 폴더 이름을 바꾸면 연결이 끊깁니다. 연결하려면 vault-map.json을 직접 고쳐야 합니다.

바뀐 구조 (main 병합, 이 Mac 설치 완료)

위 규칙 네 가지를 다시 검토한 결과입니다. 규칙1과 규칙3은 유지하고, 규칙2와 규칙4는 바꿉니다. 2026-10-29에 구현을 마치고 main에 병합했습니다(a843778). 테스트 582개와 release gate를 통과했고, 리뷰 판정은 Ready to merge입니다. 같은 날 이 Mac에도 새로 설치했습니다. doctor가 통과했고, llm-wiki 서버 하나만 연결되어 있으며, uninstall 뒤 남는 파일이 없고 재설치하면 처음 상태로 돌아오는 것까지 확인했습니다.

규칙지금바뀐 뒤
규칙1vault 하나는 폴더 하나이자 git 저장소 하나입니다. 도구 사본도 vault마다 하나입니다.유지합니다. 도구 사본은 vault 안의 CI와 release gate가 쓰므로 그대로 둡니다.
규칙2MCP 서버 하나가 vault 하나만 다룹니다. 등록은 .mcp.json과 ~/.claude.json 두 곳에 합니다.사용자 단위 서버 하나를 ~/.claude.json에 한 번만 등록합니다. 서버는 vault-map.json을 읽고 요청마다 대상 vault의 tools/wiki/cli.py를 실행합니다. 서버는 상태를 두지 않고, 호출마다 지도를 다시 읽고 대상 vault의 CLI를 -I -B 옵션으로 새로 실행합니다. 읽기와 검색은 이 세션이 닿는 vault(세션 vault, 또는 저장소에 연결된 vault)만 대상으로 합니다. 쓰기는 vault 인자를 반드시 받고, team vault를 포함해 어떤 vault에도 쓸 수 있으며, 경로는 그 vault 안의 상대 경로만 받습니다.
규칙3vault-map.json이 vault를 묶는 유일한 파일입니다. 저장소 연결은 손으로 합니다.파일은 그대로 기준으로 둡니다. link, unlink, list 명령으로 연결합니다.
규칙4폴더 이름이 project id입니다.root 경로, git remote URL, 폴더 이름 순서로 찾습니다. project id는 페이지의 project: 값으로만 씁니다.
설치와 제거install은 서버를 두 번 등록하고, doctor는 .mcp.json을 다시 만듭니다.install은 서버를 한 번만 등록하고 .mcp.json은 만들지 않습니다. doctor는 서버를 실제로 띄워 동작을 확인합니다. uninstall은 마지막 vault를 제거할 때 서버 등록과 공용 파일까지 지웁니다. uninstall한 vault는 install 하나로 다시 설치됩니다. interpreter는 patch 번호가 없는 경로로 고릅니다.
